# docs/adr — 架构决策记录（Architecture Decision Record）

> 用途：记录**已经做出的**架构/流程决定（一句话决定 + 后果 + 约束），不重复论证过程（论证在对应 RFC）。
> 何时写：RFC 通过后需要固化长期决策，或团队需要一个稳定锚点防止后续实现漂移。流程见 `docs/process/02-DESIGN-RFC.md` §4。

## 1. 命名与编号

| 项 | 规则 |
|---|---|
| 文件名 | `NNNN-<slug>.md`（与 RFC 同规则：四位零填充 + kebab-case） |
| 编号 | 独立序列（ADR 与 RFC 编号不共享）；不复用、不回填 |
| 取代 | 新 ADR 写明 `Supersedes ADR-MMMM`；被取代的 ADR 状态改 `Superseded by ADR-NNNN`，正文不改写 |
| 索引 | 新增 ADR 时同步更新本文件 §3 索引表 |

## 2. 模板骨架（复制后填写）

```markdown
# ADR NNNN — <决定一句话>

- 状态：Accepted | Superseded by ADR-MMMM
- 日期：YYYY-MM-DD
- 来源 RFC：<docs/rfc/NNNN-...>（必须存在）
- 决策者：<role>　批准人：<owner>

## 背景
<2–5 行：为什么需要这个决定，约束是什么>

## 决定
<一句话，动词开头：采用 / 禁止 / 固定 / 迁移 / 废弃>

## 后果
- 正面：<…>
- 负面：<…>
- 约束：<对后续实现/门禁的硬约束，可被 CI 或评审检查>
```
