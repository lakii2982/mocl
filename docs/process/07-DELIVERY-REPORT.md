# 07 — 交付报告（G7 的最终产物）

> 目标：把「做了什么 / 凭什么说做完了 / 还有什么没做 / 需要用户决定什么」压成一份**用户 5 分钟能读完、10 分钟能自己验收**的报告。
> 报告有两个同源交付面：**issue 评论（完整技术版，公开，审计用）** + **对话式摘要（5 段人话，见 `11-CONVERSATION-MODE.md` §5，默认给业务方）**；本地归档（私有）保存两者。两个面内容必须一致，摘要不得与完整版矛盾。开发者模式下用户直接看 issue 评论；对话式模式下用户只看对话摘要，DSH 负责保证摘要与完整版同源。
> 上游：`05-REVIEW-MERGE.md`、`06-RELEASE.md`。

## 1. 交付报告的三条硬规则

1. **每条结论指向证据**：功能声明 → PR/commit；质量声明 → 命令 + 退出码；发布声明 → Release URL。
2. **不写未发生的事**：未验证、未采集、未覆盖的一律显式写「未覆盖 / UNCOLLECTED」，禁止用「应该」「预计」「基本」。
3. **可验收性优先**：必须含「如何验收」段，命令可直接复制执行；用户不需要读代码即可判定。

````markdown

- 交付角色：implementer / verifier / reviewer / release-manager（各自独立上下文）
- 用户：<owner>

## 1. 做了什么（用户视角）
<3–6 条业务语言，讲清「你的场景现在能怎样」，不堆技术细节>

## 2. 怎么用
```bash
<安装/升级/使用的最短命令序列，≤5 行>
```
````

## 3. 发布与归档

| 动作 | 命令 | 判据 |
|---|---|---|
| 归档到本地 | 写入 `.agentspec/runs/<iso>/DELIVERY-REPORT.md` | 文件存在且 ≥ 模板 10 段 |
| 发到 issue（公开） | `gh issue comment <n> --body-file .agentspec/runs/<iso>/DELIVERY-REPORT.md` | 评论 URL 存在 |
| 发对话摘要（对话式） | 合并/发布后由 DSH 把本文的 5 段人话摘要（`11` §5）发到对话 | 摘要与 issue 完整版同源、不矛盾 |
| 关联 Release | Release notes 末尾追加 `交付报告：<issue 评论 URL>` | `gh release view` 可见 |
| 用户验收后归档 | `gh issue edit <n> --add-label "status/accepted"`；报告路径写入 `CHANGELOG.md` 版本段（可选） | label 存在 |

## 4. 质量自检（scribe 在发出前跑）

| # | 检查 | 判据 |
|---|---|---|
| Q-1 | 10 段齐全 | grep 每段标题均存在 |
| Q-2 | 证据表无空退出码 | 每行退出码为数字 |
| Q-3 | 无「应该/预计/基本/大概」等模糊词 | `grep -nE '应该|预计|大概|基本'` 为空或无用于结论的句子 |
| Q-4 | 已知限制段非空 | 至少 1 条或明确写「无已知限制」 |
| Q-5 | 待决策段有默认项 | 每个决策项含默认选项 |
| Q-6 | 无个人路径/凭据 | `node tools/leak-scan.mjs` exit 0 |
| Q-7 | 版本与 tag 一致 | `package.json` version == tag 去 `v` |

## 5. 常见错误

| 错误 | 后果 | 修正 |
|---|---|---|
| 只贴 CI 绿不贴本地证据 | 用户无法复现 | 证据表含本地命令 |
| 把已知限制写成「暂无」 | 隐藏问题，验收后爆雷 | 逐条列，含绕过方式 |
| 待决策项没有默认值 | 用户不知如何回复 | 每项给默认 A |
| 报告正文出现未验证数字 | 违反证据协议 | 删数字或补命令 |
| 交付报告与 PR 描述矛盾 | 不可信 | 以 G4 证据为准重写 |
